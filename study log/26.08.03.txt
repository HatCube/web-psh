통합구현
연계 데이터 구성하기

통합구현의 정의
>서로 다른 시스템이나 모듈을 연결하여 데이터를 주고받고, 하나의 서비스처럼 작동하도록 만드는 과정
>사용자의 요구사항을 해결하기 위해 여러 시스템의 기능과 데이터를 연계 통합하여 하나의 서비스 환경을 구성함
>송수신 방식,아키텍처,모듈 구현 등을 고려하여 시스템 간 데이터 교환 및 처리를 수행

통합구현이 필요한 이유
1.이기종 시스템 간 데이터 연계 필요성 증가
2.서비스 확장성과 재사용성 확보
3.운영 효율성과 데이터 품질 향상
4.신규 서비스 창출

통합 구현의 주요 기능과 요소
1.데이터 생성 및 송신
2.데이터 변환 및 매핑
3.데이터 수신 및 정제
4.연계 데이터 관리
5.네트워크 및 프로토콜 관리

연계 요구사항 분석
>시스템 연결 전 어떤 데이터를, 어떤 방식으로 주고 받을 지 미리 결정하는 사전 작업

요구사항 분석을 해야하는 이유
1.사용자 요구사항을 구체화하기 위해
2.형식,범위,주기,전송 방식 명확화
3.확장성 및 오류 예방
4.서비스 품질 보장

연계 요구사항 분석 절차
1.현행 시스템 및 운영 환경 파강(하드웨어,소프트웨어,ERD 등)
2.사용자 요구사항 수집 (인터뷰, 설문조사, 체크리스트, FGI 등)
3.연계 데이터 분석
4.결과 정리(문서로 작성)

요구사항 분석에 앞서 필요한 입력물
>시스템 구성도
>응용 어플리케이션 구성
>ERD

출력물
>요구사항 분석서 : 요구사항 ID, 유형, 내용, 제약/종료 조건
>인터페이스 정의서 : 연계 데이터 항목, 형식, 전송 방식, 주기 등을 명시
>회의록 : 참석자, 논의 내용, 결정 사항 및 향후 일정 기록

연계 데이터 표준화

연계 데이터 식별
>서로 다른 시스템이 데이터를 주고받기 위해 필요한 데이터를 찾아내고, 동일한 기준으로 정의하는 과정

연계 데이터 식별의 필요성
>단순히 데이터를 전달하는 것을 넘어 데이터의 정확성과 안정적인 교환을 보장하기 위함
>시스템 간 데이터 불일치 예방
>코드 체계 불일치 문제 예방
>데이터 중복 및 누락 방지
>개발 생산성 및 유지보수성 향상

연계 데이터 식별 절차
1.연계 대상 데이터 추출 및 식별 
>송수신 시스템 간 주고받아야 할 데이터를 테이블 및 컬럼 단위로 추출
2.연계 데이터 매핑 및 변환 규칙 정의
>송수신 시스템 간 항목을 1:1 또는 N:1등의 관계로 연결하고 변환 규칙을 수립
3.연계 데이터 식별자 정의
>전송되는 데이터를 유일하게 구분할 수 있는 식별키(PK) 또는 Transaction ID 정의
4.연계 데이터 표준화 수행
>연계 데이터 용어, 형식, 코드 체계를 공통 기준에 맞춰서 표준화
5.연계 데이터 명세서 작성
>식별 및 표준화가 완료된 연계 데이터를 최종 문서로 만들어 체계화

연계 메커니즘 구성하기
>개발하고자 하는 응용 소프트웨어와 외부 시스템인 연계 대상 모듈 간의 데이터 송수신 요구사항을 충족하고,데이터 형식,전송,보안,신뢰성을 고려하여 데이터를 안정적이고 효율적으로 교환하기 위한 기술적 체계와 프로세스

연계 메커니즘의 구성 요소
1.송신 시스템
2.수신 시스템
3.인터페이스 테이블 또는 파일
4.연계 서버 또는 어댑터
5.로깅 및 모니터링

연계 방식
송/수신 시스템 간 데이터를 교환할 때 정의할 내용
>사용할 전송 프로토콜
>사용할 데이터 형식
>사용할 연계 미들웨어 또는 연계 엔진

연계 데이터 생성 및 추출
>운영DB 또는 어플리케이션에서 필요한 데이터를 선별,가공하여 타 시스템으로 송신할 수 있도록 연계 대상 데이터를 생성/추출하는 작업
>생성/추출 형태 : 인터페이스 테이블,파일, 메시지

인터페이스 테이블 (Interface Table,I/F Table)
>데이터를 다른 시스템에게 전달하기 위해 별도로 만든 데이터베이스 테이블

VPN (virtual Private Network 가설사설망) 보안 방식을 결정한다
>인터넷 위에 전용 통신망을 만드는 기술
>실제로는 인터넷을 사용하지만 터널을 만들어 안전하게 통신한다
>재택근무,클라우드에서 많이 사용한다
>구축비용이 저렴하고 인터넷만 있으면 사용이 가능하다
>인터넷 품질 영향을 받는다
