애플리케이션 배포 환경 구성
1. 소스코드 빌드 과정 이해
빌드 : 소스코드를 실행할 수 있는 상태로 변환하는 과정, 프로그래밍 언어와 유형에 따라 빌드 과정이 다르다
- 컴파일 언어(C, C++ 등)
ㄴ 기계어로 바로 변환되어 실행되기 때문에 가장 속도가 빠르고 보안에 유리하다. 하지만 소스가 변경될 때마다 컴파일 과정을 통해서 빌드 작업을 수행하기 때문에 과정이 오래걸린다.
- 바이트 코드 언어(Java, C# 등)
ㄴ 컴파일의 결과물이 실행 파일이 아닌 'class'라는 바이트 코드 파일로 생성되고 가상 실행 환경인 JRE,CLI에서 한 줄씩 실행하는 방식으로 빌드된다. JRE, CLI 환경에서 실행될 때 기계어로 변환되며, 컴파일 언어에 비해 빌드 과정이 빠르다.
- 인터프리터 언어(JavaScript, Python 등)
ㄴ 컴파일 언어와 다르게 한 줄씩 번역되어 실행된다. 인터프리터 언어는 컴파일하는 과정에서 메모리가 훨씬 적게 소모되고 빠른 시간에 컴파일을 진행할 수 있다.

2. 애플리케이션 배포 환경
배포 : 개발자 또는 사용자가 애플리케이션을 실행, 테스트할 수 있도록 컴파일된 프로그램, 실행에 필요한 리소스(이미지, 환경 설정 파일)를 서버상의 적합한 위치로 이동하는 작업
- 애플리케이션 배포는 해당 애플리케이션의 동작 환경의 영향을 받는다.
- 웹 애플리케이션의 경우 웹 서버, WAS(Web Application Server)를 동작 환경으로 사용한다

웹 서버(Web Server)
- 사용자의 http 요청을 받아 웹 컨테이너에 요청을 전달하고 결과값을 받아와 사용자에게 전송하는 역할을 수행한다.
- 애플리케이션 배포시 이미지, 단순 HTML과 같은 정적인 리소스를 배포하며, 정적 리소스를 빠르고 안정적으로 처리한다.

웹 애플리케이션 서버
- 사용자의 요청을 받아 동적인 처리를 수행하는 프로그램 실행 부분을 배포한다.
- WAS 구성 및 운용을 위한 표준 규격을 정하고 있으며, 제품마다 배포 방식과 설정이 일부 다르다

애플리케이션 배포환경 구성하기
1. 프로젝트 배포 관리 요건을 분석하고 배포 환경 구성 방안을 기획한다
- 프로젝트의 애플리케이션의 기술적인 특성을 확인하고 배포 방식 결정
ㄴ 애플리케이션의 개발 언어 확인
ㄴ 프로젝트에 적용되어 있는 개발 도구, 개발 환경을 확인
ㄴ 애플리케이션의 유형을 확인(모바일, 웹, C/S기반 시스템 등)
ㄴ 배포 대상 리소스의 유형을 확인한다(배포 단위를 파악 : Jar, War, ear 등)
ㄴ 배포 대상 리소스 유형 확인(html, 프로그램, 공통코드를 분류)
ㄴ 배포 시 연계하여 처리하고자 하는 프로젝트 요건을 확인

- 개발하려는 애플리케이션의 인프라 환경을 확인하고 대상 서버를 확인한다
ㄴ 개발하려는 애플리케이션 서버 구성 환경을 확인한다
ㄴ 리소스 유형별 배포 대상 서버를 확인한다
ㄴ 분산 배포 대상을 확인한다
ㄴ 통합 빌드 배포 구성도를 작성한다

2. 애플리케이션 배포를 위한 도구와 시스템을 선정한다
- 소스 형상관리 도구를 선정한다
ㄴ 일반적으로 애플리케이션 개발 기간 중에는 일시적인 사용과 비용 측면을 고려하여 오픈소스 기반의 형상관리 도구(Maven, CVS, Subversion 등)를 사용하고, 배포 이후 운영 환경에서는 안정적인 운영을 위해 상용 형상관리 도구를 도입하여 사용한다.
- 빌드 도구를 선정한다
ㄴ 애플리케이션 빌드, 배포 스크립트 작성을 위한 빌드 도구를 선정한다.
ㄴ 빌드 도구는 일반적으로 도입된 개발 도구상에 임베디드 되어 제공되는데, 프로젝트 차원의 전체적인 통합 빌드 수행을 위해서는 별도의 빌드 도구를 사용해야 한다.
ㄴ 개발 언어, 개발 도구별로 표준적으로 사용하는 빌드 도구가 정의되어 있으며, 해당 기준에 맞추어서 빌드 도구를 선정한다(Java는 Eclipse를 사용한다)

- 빌드 스케줄 관리 도구를 선정한다
ㄴ 지속적인 통합, 빌드 환경의 구성이 필요한 경우 빌드 스케줄 도구를 사용한다.
ㄴ 빌드 스케줄 도구도 빌드 도구에 맞추어서 표준적으로 사용되는 도구가 있으며, 해당 도구를 선정한다.

- 테스트 도구를 선정한다
ㄴ 자동화된 테스트 수행이 필요한 경우 테스트 도구를 선정한다
ㄴ 테스트 도구 선정 시에는 해당 테스트 도구가 사용하는 빌드 도구, 형상관리 도구와 연계가 가능한지, 호환성을 제공하는 버전인지 확인한다.
ㄴ 테스트 도구는 테스트 대상별로 여러 유형이 존재하며, 반영하고자 하는 범위 내에서 선정한다.

- 검토 대상 코드 인스펙션 점검 도구를 파악한다
ㄴ 발주사 또는 운영중인 시스템에서 사용 중인 코드 인스펙션 점검 도구가 있거나 RFP상에 명시된 도구가 있다면, 해당 도구를 우선적으로 사용할 수 있는지 확인한다.

- 애플리케이션 개발에 적합한 코드 인스펙션 도구를 선정한다
ㄴ 오픈소스 기반의 도구를 사용하고자 하는 경우에는 해당 도구의 기술 지원이 가능한 인력의 존재 여부를 판단해야 한다
ㄴ 상용 제품을 도입하는 경우 프로젝트 기간 중 적절한 지원이 가능하도록 기술 지원 사항을 포함하여 선정한다.

애플리케이션 배포 환경 설정
1. 애플리케이션 배포 단위
- jar(Java Archive)
ㄴ Java 라이브러리, 리소스, property 파일들을 포함한다.
ㄴ 프로그램에서 참조하는 라이브러리, 구현된 비즈니스 서비스를 배포할 때 jar 단위로 패키징하여 배포한다.
- war(Web Archive)
ㄴ 웹 컨테이너에 배포되는 배포 형식으로 Service, jar 파일과 WEB-INF 폴더에 들어있는 web.xml 파일로 구성.
ㄴ 웹 컨테이너상에 배포되어 독립적인 UI단 웹 애플리케이션 서비스를 제공할 수 있다.

- ear(Enterprise Archive)
ㄴ jar와 war를 묶어서 하나의 완성된 웹 애플리케이션 서비스를 제공할 수 있다.

2. 형상관리 시스템
서비스 제공 대상 형상 항목을 식별하여 기준선을 설정하고, 형상 항목 변경 과정에서 점검, 검증 등의 체계적인 통제를 통해 형상 항목 간의 일관성과 추적성을 확보하기 위한 시스템

- 형상관리의 범위
ㄴ 신규 프로젝트 및 보완 개발, 업무 시스템의 운영/유지보수, 전산 설비 및 시스템 소프트웨어 등과 관련된 작업, 사용자 파일 관리 등을 포함한다.

- 형상관리 시스템에서 사용하는 용어
ㄴ 형상관리 : 소프트웨어의 전체 생명 주기의 관리
ㄴ 형상항목 : 형상관리 대상이 되는 항목
ㄴ 기준선 : 공식적으로 검토되고 협의되어 향후 기준이 되는 형상 항목의 집합체
ㄴ 마이그레이션 : 개발 완료된 시스템이 운영 단계로 전환될 때 관련 소스 파일을 저장 공간으로 이관시키는 잘업
ㄴ 리포지터리 : 관리 대상을 형상관리 시스템으로 일괄 전송하여 압축, 암호화한 후에 저장, 관리하는 저장 공간
ㄴ 워크플로 : 형상관리 활동을 수행하기 위해 미리 정해진 절차가 형상관리 시스템 안에 구현되어 있는 것
