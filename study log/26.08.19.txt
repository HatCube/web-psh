1. 어플리케이션 배포 환경 구성
1-1.소스코드 빌드 과정의 이해
- 컴파일 언어(기계어로 변환되어 실행 C,C++)
- 바이트코드 언어(바이트코드로 변해서 JRE가 실행 Java, C#)
- 인터프리터(한 줄 씩 번역 JS, Python)

1-2.어플리케이션 배포 환경 
- 웹서버(html,이미지와 같은 정적 리소스 처리)
- 웹 애플리케이션 서버(동적인 처리 백엔드 처리)

애플리케이션 배포 환경 구성하기
1.프로젝트 배포 관리 요건을 분석하고 배포 환경 구성 방안을 계획한다
- 애플리케이션의 기술적인 특성을 확인하고 배포 방식을 정의한다
ㄴ개발 언어의 확인
ㄴ프로젝트에 적용되어 있는 개발 도구, 개발 환경을 확인
ㄴ애플리케이션의 유형을 확인한다
ㄴ배포 대상 리소스의 유형 확인(JAR,WAR,EAR)
ㄴ배포 대상 리소스 유형을 확인한다(이미지,html,서버 프로그램...)
ㄴ배포시 연계하여 처리하고자 하는 프로젝트 요건 확인
-개발하려는 애플리케이션의 인프라 환경을 확인하고 배포 대상 서버를 확인
ㄴ개발하려는 애플리케이션의 서버 구성 환경을 확인한다
ㄴ리소스 유형별 배포 대상 서버를 확인한다(소스코드는 형상관리 시스템을 통헤 관리하고 배포한다)
ㄴ분산 배포 대상을 확인
ㄴ통합 빌드 배포 구성도를 작성

2.애플리케이션 배포를 위한 도구와 시스템 선정
- 소스 형상관리 도구를 선정한다
- 빌드 도구를 선정한다
- 테스트 도구 선정 
- 검토 대상 코드 인스펙션 점검 도구를 파악한다
- 애플리케이션 개발에 적합한 코드 인스펙션 점검 도구 선정

2.애플리케이션 배포 환경 설정
2-1.애플리케이션 배포 단위
- jar(Java archive)
ㄴJava 라이브러리,리소스, 설정파일 들을 포장한다
- war(Web Archive)
ㄴ웹 컨테이너에 배포, Servlet,Jar파일, WEB-INF 안에 있는 web.xml파일로 구성
- ear(jar와war를 묶어서 하나의 완서오딘 웹 어플리케이션 서비스를 제공

2-2.형상관리의 범위
ㄴ신규 프로젝트 및 보완 개발, 업무 시스템의 운영'윶;/소수, 전산 설비 및 시스템 스포트웨어 등과 관련된 작업, 사용자 파일 관리
- 형상관리 시스템에서 사용하는 용어
ㄴ형상관리 : 소프트웨어 전체 생명 주기를 지속적으로 관리하는 것
ㄴ형상항목 : 관리의 대상이 되는 항목,소스파일,문서,기타사항
ㄴ기준선 : 공식적으러 검토되고 협의되어 향후 기준이 되는 형상 항목의 집합체
ㄴ마이그레이션 : 개발 완료된 시스템이 운영 단계로 전환될 때 관련 소스 파일을 저장공간으로 이관시키는 작업 
ㄴ리포지터리 : 관리 대상을 일괄 전송하여 압축, 암호화 한 후에 저장, 관리하는 저장공간을 의미
ㄴ워크플로 : 형상 관리 활동을 수행하기 위해 미리 정해진 절차
ㄴ 반출(check out) : 형상 항목을 수정하기 위해 리포지터리로부터 전송받는것
ㄴ반입(check in) : 반출된 형상항목을 변경 후 다시 형상 리포지터리로 전송하는 것
