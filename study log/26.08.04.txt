내외부 연계 모듈 구현 환경

내외부 연계
서로 다른 시스템이 데이터를 주고받으며 함께 동작하도록 연결하는 것
최근 회사에서는 하나의 프로그램만 사용하는 경우가 거의 없다
예를 들어 쇼핑몰에서는 회원관리 프로그램, 주문 프로그램, 결제 시스템, 배송 시스템, 재고 시스템 등 여러 프로그램이 각각 존재한다

이 시스템들이 서로 정보를 주고 받아야 정상적으로 업무가 진행된다.

내외부 연계 모듈 구현 환경
서로 다른 시스템간 데이터 교환 및 서비스 연계를 실현하기 위해 필요한 기술적 물리적 실행 환경

- 데이터베이스
- 인터페이스 테이블
- 프로그램
- API
- 네트워크
- 서버
- 보안
- 로그 시스템

구현 방식
1.DBMS 오브젝트
- DBMS내부에서 제공하는 기능을 이용하여 데이터를 자동으로 연계하는 방식
- 프로그램을 별도로 작성하지 않고 데이터베이스 자체기능을 이용하여 다른 시스템으로 데이터를 전달한다.
대표적으로Trigger,Procedure를 사용한다
- 쇼핑몰에서 주문이 발생하면 > Trigger 실행 > 인터페이스 테이블에 저장 > 수신 시스템이 읽어간다
장점
- 구현이 비교적 쉽다
- 별도의 프로그램이 적다
- DB내부에서 처리하므로 속도가 빠르다
- 소규모 시스템에 적합하다
단점
- DB에 부하가 발생한다
- DBMS에 종속된다
- 시스템이 커질수록 관리가 어렵다
- 확장성이 낮다

2.프로그램 코드
Java,Spring,Python 등의 프로그래밍 언어를 이용하여 연계 프로그램을 직접 개발하는 방식이다.
- 데이터를 추출하고 필요한 형태로 형변환 후 다른 시스템으로 전송하는 모든 과정을 개발자가 직접 구현한다.
- DB연결, 데이터 조회, 데이터 검증, 데이터 변환, JSON 또는 XML 생성, API호출, 로그기록, 오류 처리

장점
- 자유롭게 개발이 가능하다
- 다양한 기능을 추가할 수 있다
- 복잡한 업무 처리에 적합하다
- 유지보수가 비교적 쉽다
단점
- 개발 시간이 오래 걸린다
- 개발자의 기술 수준에 영향을 많이 받는다
- 테스트가 많이 필요하다

3.EAI / ESB 방식
기업에서 사용하는 수많은 시스템을 하나의 통합 플랫폼으로 연결하는 방식
- 기업에는 ERP,CRM,인사,그룹웨어,물류,회계,모바일 앱 등의 수십개의 시스템이 존재한다
- 중간에 EAI 또는 ESB를 두어 모든 데이터를 관리한다
EAI : 기업 내부 시스템을 하나로 통합하는 미들웨어
ESB : 서비스간 데이터를 전달하는 버스(BUS)형태의 미들웨어

장점
- 대규모 시스템에 적합하다
- 시스템 추가가 쉽다
- 중앙에서 관리할 수 있다.
- 쟁애 관리가 쉽다
단점
- 구축비용이 높다
- 구조가 복잡하다
- 운영 인력이 필요하다

4.Web Service 방식
- 인터넷이나 네트워크를 이용하여 표준화된 방식으로 시스템 간 데이터를 주고받는 방식
- 예전에는 SOAP를 많이 사용했지만, 최근에는 대부분 REST API를 이용하여 데이터를 주고받는다

장점
- 개발이 쉽다
- 다양한 언어와 플랫폼에서 사용할 수 있다
- 확장성이 높다
- 클라우드 환경에 적합하다
단점
- 네트워크 장애의 영향을 받는다
- 보안 설정이 중요하다
- API 버전 관리가 필요하다

5.API / 클라우드 연계 방식
- 클라우드와 MSA환경 REST API, gRPC,Kafka 등의 이벤트 스르티밍을 활용하여 시스템을 연계하며 API Gateway와 Service Mesh 를 통해 서비스 간 통신, 보안, 모니터링을 관리한다.

2.수신 시스템의 테이블을 생성하고 데이터를 입력한다
- 공고 정보 테이블
- 코드 테이블
- 수신용 오류 코드 테이블

3.수신 디렉터리 생성하기
- 연계,로그,오류 로그 파일이 위치할 수신 디렉터리 생성하기

4.수신 시스템의 파일 정의서를 확인 및 점검
- 각 테이블 정의서 내용의 구조 및 각 항목의 데이터 타입과 길이 등을 확인한다

송/수신 시스템의 연계 응용 프로그램을 개발한다
1.자바 개발 환경을 확인 및 점검한다
- 자바 개발 도구 설치 여부
- 설치된 자바 버전
- 설치 경고
- 환경 변수 설정 상태
- 정상적인 명령어 실행 여부

명령어와 옵션을 통해 설치된 자바 개발 도구의 버전을 확인할 수 있으며, 설치 경로 등 정상적인 설치 여부와 설치 환경을 확인한다.

2.송신 시스템의 연계 응용 프로그램 설계서를 작성한다
- 개발할 송신 시스템 연계 응용 프로그램의 설계서를 작성한다
- 프로그램 설계서는 다음 내용을 포함하여 작성
ㄴ프로그램ID
ㄴ프로그램 명
ㄴ인터페이스 파라미터
ㄴ상세 처리 로직
ㄴ오류 처리 방법
ㄴ입출력 파일 정보

상세 처리 로직은 자바 언어의 문법으로 구체적이며 중요 내용의 누락 없이 작성한다.

송신 시스템 연계 응용 프로그램의 상세 처리 절차
1.데이터베이스 연결 생성
2.파일 생성
3.데이터 추출
4.코드 매핑
5.데이터 변환
6.연계 파일 기록
7.처리 단계별 로그 기록
8.오류 로그 기록

수신 시스템의 연계 응용 프로그램 설계서를 작성한다.
1.수신 시스템 연계응용 프로그램의 설계서를 작성한다.
2.프로그램 설계서의 상세 처리 로직을 작성한다.

수신 시스템 연계 응용 프로그램의 상세 처리 절차
1.데이터베이스 연결 생성
2.수신용 파일 생성
3.수신용 연계 파일을 한 행 씩 로드한다.
- 수신용 연계 파일을 읽기모드로 열고, 파일의 데이터를 한 행 씩 로드한다.
4.데이터를 각 속성으로 분할한다
- 파일에서 로드한 데이터를 구분자인 콜론( : ) 을 기준으로 각 속성으로 분할한다
5.각 속성의 데이터 유효성을 점검한다
- 비어있는 문자열 여부
- 필수 값 누락 여부
- 데이터 타입
- 데이터 길이
- 날짜 형식
- 숫자 형식
- 허용된 값인지 여부
6.코드의 유효성을 확인하다
- 분할된 속성 중 코드가 존재할 경우, 해당 코드가 수신용 코드 테이블에 존재하는지 확인한다
7.수신용DB에 데이터를 반영한다
- 행의 모든 속성이 데이터 유효성 점검을 통과하여 유효한 경우 변경 구분자에 따라 수신용 DB의 공고 정보 테이블에 데이터를 반영한다.
8.처리 단계별 로그를 기록한다
- 연계 파일 읽기 모드 생성
- 연계 파일 열기
- 데이터 로드
- 각 속성 분할
- 데이터 유효성 점검
- 코드 유효성 확인
- 수신용 DB 반영
- 처리 완료
9.처리 단계별 오류를 기록한다
- 처리 단계별로 오류가 발생하거나 데이터 유효성 점검 결과 유효하지 않은 값이 발견되면 수신용 오류 코드 테이블을 참고하여 수신용 오류 로그 파일에 기록한다.

송수신 연계 응용 프로그램을 단독 배치형식으로 개발한다
- 장성한 송/수신 시스템의 연계 응용 프로그램 설계서 내용을 자바 언어를 사용하여 단독 배치 형식으로 개발한다
- 단독 배치 형식은 웹 화면이나 사용자의 직접 요청 없이 자바 프로그램이 독립적으로 실행되어 정해진 작업을 처리하는 방식이다.

송신 시스템에서 보낸 데이터가 수신 시스템까지 문제 없이 정확하게 전달 되는지 미리 확인하는 과정

단순히 기능이 실행되는지만 확인하는 것이 아니라 다음의 항목까지 포함하여 종합적으로 검증한다
1.데이터 무결성
- 데이터가 누락,중복,변경 없이 정확하게 전달되었는지 확인한다.

연계 모듈 테스트 설계의 필요성
연계 모듈은 여러 시스템을 연결하는 역할을 하기 때문에 작은 오류 하나만 발생해도 여러 시스템에 동시에 영향을 줄 수 있다
1.무결성
- 송신DB의 데이터가 수신 DB에 누락,중복,변형 없이 정확하게 반영되었는지 검증
2.업무 연속성 확보
- 장애나 오류가 발생하더라도 정상적으로 복구할 수 있는지 확인하고, 로그를 통해 처리 과정을 추적할 수 있는지 검증
4.보안성 검증
- 데이터 전송 구간 암호화, 접근 제어, 인증, 인가와 같은 보안 기능이 정상적으로 동작하는지 확인한다

5.최신환경에서의 필요성
- 클라우드 및 MSA기반 시스템에서는 수십개에서 수백개의 API와 서비스가 실시간으로 연계된다.
- 사람이 직접 하나씩 테스트 하는 것은 거의 불가능하다
- 반복적인 테스트를  사람이 직접 수행하기보다는 자동화된 연계 데트스와 모니터링 체계를 구축할 필요가 있다

연계 모듈 테스트 설계 절차
- 연계 모듈 테스트 설계는 무작정 테스트를 시작하는 것이 아니라 일정한 순서에 따라 체계적으로 수행한다.
