연계 오류의 세 가지 유형
 - 연계 시스템 오류 : 인터넷이 끊기거나, 연계 서버/수신 서버 컴퓨터가 꺼진 경우, 방화벽 포트 차단 등 네트워크 및 하드웨어/환경적 장애

 - 연계 데이터 오류 : PK 중복, 필수 값 누락, 코드 불일치, 데이터 타입 불일치 등 데이터 자체의 정합성/무결성 결함

연계 오류 식별 방법
로그 파일 조회 : 연계 서버, 송수신 어댑터, DB 등의 로그 파일을 확인하여 오류 메시지 및 오류 코드 식별
모니터링 시스템/관제 도구 활용 : 연계 모니터링 화면에서 미처리/실패 건 발생 알림 및 상태 값 확인
I/F 테이블 조회 : 처리 상태 컬럼 조건을 통한 오류 건 검색

연계 오류 원인 분석 방법
오류 코드 및 메시지 해석 : 에러코드와 예외 추적 내역 분석

암호화 알고리즘
SEED : 1999년 한국인터넷진흥원(KISA)과 국내 암호학자들이 자체 개발한 128비트 대칭키 블록 암호 알고리즘
- 개발 배경 : 미국 중심의 암호 기술 수입 의존도를 낮추고 국내 전자상거래 및 인터넷 금융의 보안을 강화하기 위해 국산 표준으로 개발되었다.
- 주요 특징
ㄴ 블록 크기 : 128비트(16바이트)
ㄴ 키 길이 : 128비트, 256비트
ㄴ 구조 : 파이스텔 구조 기반
ㄴ 규격 : 대한민국 국가 표준
ARIA : 2004년 국가정보원과 산학연 전문가들이 개발한 국가 표준 대칭키 블록 암호화 알고리즘
- 개발 배경 : 기존 SEED 알고리즘이 경량 환경이나 경량화 기기, SW 경량화 환경에서 효율이 떨어지는 단점을 보완하고 AES 알고리즘과의 경량/경쟁 호환성을 위해 개발되었다
- 주요 특징
ㄴ 블록 크기 : 128비트
ㄴ 키 길이 : 128, 192, 256비트 지원
ㄴ 구조 : SPN 구조
ㄴ 장점 : 경량화 환경에 유리하며, 하드웨어 및 소프트웨어 구현 시 비트연산 위주로 동작하여 속도가 빠르고 경량 기기에 적합하다

AES : 
- 2001년 미국 표준기술연구소가 공모를 통해 지정한 세계적 표준 대칭키 블록 암호 알고리즘이다
- 개발배경 : DES의 키 길이가 짧아 해킹 위험이 높아짐에 따라 전 세계 표준으로 활용할 강력한 암호화 표준의 필요성으로 탄생했다.
- 주요 특징
ㄴ 블록 크기 : 128비트
ㄴ 키 길이 : 128비트, 192비트, 256비트
ㄴ 구조 : SPN
ㄴ 장점 : 안정성, 속도, 메모리 효율성이 뛰어나며 현재 전 세계 대부분의 연계보안에서 가장 널리 쓰이는 사실상의 글로벌 표준이다.


암호화 KEY를 관리하는 방식
1. KEY VAULT(키 볼트)
 - 소프트웨어 기반의 클라우드 암호화 키/비밀정보 관리 서비스
 - 보관 대상 : DB 암호화 키 뿐만 아니라 API 인증키, 비밀번호, SSL/TLS 증명서 등 다양한 비밀정보를 한 곳에서 관리한다
 - 접근 제어 : 어플리케이션이 Key Vault에 접근할 때 정당한 권한이 있는지 확인한 후 키를 제공하거나, Vault 내부에서 직접 암복호화를 수행해준다.

2. HSM(Hardware Security Module)
 - 암호화 키의 생성, 보관, 처리 연산만을 전담하도록 특별히 제작된 '특수 물리 하드웨어 장비'
 - 물리적 보안성 : 장비 내부의 키는 절대 외부로 추출할 수 없도록 설계되어 있다
 - 침입 탐지 및 자멸 기능 : 누군가 장비를 강제로 열거나 물리적인 공격을 시도하면 내부에 저장된 키를 즉시 하드웨어 수준에서 파기한다.
 - 연산 전담 : 암/복호화 연산을 암호화 전용 하드웨어칩이 직접 수행하므로 서버의 CPU 부하를 줄여준다.


암/복호화 알고리즘 방식 파악

1. 대칭키 암호화 : 하나의 암호키로 암호화 복호화를 수행
장점
 - 매우 빠르다
 - 대용량 데이터에 적합

단점
 - 키를 안전하게 전달해야 한다

2. 비대칭키 암호화 : **공개키를 통해 암호화하고 **개인키를 통해 복호화 한다.

** 공개 키(Public Key) : 누구나 볼 수 있도록 공개된 키
 - 데이터를 암호화 하거나, 전자서명을 검증할 때 사용
 - 인터넷이나 연계 시스템을 통해 누구에게나 자유롭게 배포할 수 있다.
 - 공개 키로 암호화된 데이터는 오직 그와 짝을 이루는 개인키로만 복호화 할 수 있다.
 - 공개 키가 외부에 노출되어도 해당 키로는 데이터를 복호화 할 수 없기 때문에 안전하다

** 개인 키(Private Key) : 소유자 본인만 안전하게 보관해야 하는 비밀 키
 - 암호화된 데이터를 복호화 하거나, 전자 서명을 생성할 때 사용한다.
 - 절대로 외부에 유출되어서는 안되며, HSM이나 Key Vault같은 보안 저장소에 안전하게 보관해야 한다.
 - 개인 키를 분실하거나 유출당하면 암호화된 데이터가 해독되거나 타인이 나를 사칭할 수 있게 된다.

[문제 1] 전송 구간 보안: 공공 Wi-Fi 환경의 중간자 공격(MITM) 대응
시나리오
A 온라인 쇼핑몰 개발팀은 모바일 앱 사용자들로부터 계정이 도용되거나 주문 금액 및 계좌번호가 변경되어 결제되는 기이한 장애 제보를 받았습니다. 조사 결과, 피해를 본 사용자들은 대부분 암호화되지 않은 공공 Wi-Fi 환경에서 HTTP 통신을 이용해 앱 접속 및 주문을 진행한 것으로 확인되었습니다.

질문

네트워크 통신 관점에서 현재 발생한 보안 위협의 명칭과 원인을 설명하시오.
보안 위협 명칭 : 중간자 공격(MITM : Man-in-The-Middle), 패킷 스니핑
 - 송수신 간 공공 와이파이 등에서 암호화되지 않은 HTTP 사이트에 로그인하면 공격자가 패킷 분석 도구를 통해 네트워크 중간에서 지나가는 데이터를 몰래 수집하여 내용을 보거나 주문금액, 계좌번호 등을 임의로 변조할 수 있기 때문이다.
 - 이는 전송 구간에서 암호화를 하지 않아 평문 데이터(RAW-DATA)가 그대로 전달이 된 것이 원인이다.

이를 해결하기 위해 전송 구간(채널)에 적용해야 하는 보안 기술과 그 해결 메커니즘을 서술하시오.
 - 전송 구간에서 전달되는 개인정보를 암호화하거나 통신 채널 자체를 암호화하여 데이터를 전송해 데이터가 유출되더라도 키가 없으면 정상적인 데이터를 볼 수 없도록 한다. 이를 통해 도청 및 변조를 차단한다.
 - https 전송 구간 암호화 적용

[문제 2] 데이터 저장 보안: DB 암호화 및 유출 시 무력화
시나리오
B 병원의 시스템 관리자 계정이 해킹당하여 전체 환자 DB 테이블이 외부로 유출되었습니다. 유출된 데이터에는 환자의 이름, 전화번호, 주민등록번호, 계좌번호, 진료 기록이 포함되어 있습니다. 다행히 해당 병원은 관련 법 및 규제(개인정보보호법 등)를 준수하여 민감 데이터를 평문이 아닌 암호화된 상태로 관리하고 있었습니다.

질문

DB 암호화가 적용되어 있을 때, 공격자가 데이터를 탈취하더라도 데이터가 보호되는 핵심 이유(데이터 탈취 무력화 개념)를 서술하시오.
 - 공격자가 암호화된 데이터를 탈취하더라도, 원래의 키가 없으면 암호화된 데이터를 풀어낼 수 없고, 따라서 평문의 데이터를 얻어낼 수 없게 된다.
 - 데이터베이스 내 민감 정보가 암호화되어 저장되어 있으면, 공격자가 db 테이블 전체를 탈취하더라도 복호화 키를 소지하지 않는 한 원래의 평문을 해독하거나 악용할 수 없기 때문이다.
즉, 데이터의 물리적 유출 사고가 발생하더라도 실제 정보 노출 피해를 차단할 수 있다.

DB 내 모든 컬럼을 암호화하지 않고 주민등록번호, 계좌번호 등 특정 민감 데이터만 선택적으로 암호화하는 이유를 성능 및 운영 측면에서 설명하시오.
 - 모든 데이터를 전부 암호화하면 검색, 정렬, 성능, 운영 편의성에 영향을 줄 수 있기 때문에, 데이터의 중요도와 활용 방식을 고려해 암호화 대상을 결정해야 한다.
 - 중요도는 법적 규제 대상이거나 민감도가 높은 고유식별정보/금융정보 위주로 우선 암호화하고, 자주 검색되는 정보는 접근 제어나 마스킹 등을 조합해 성능과 보안의 균형을 맞춘다.

	- HMAC/전자서명 : 비밀키나 공인인증서를 이용해 데이터에 서명/인증 코드를 첨부함으로써 무결성 검증과 동시에 송신자의 신원확인까지 수행한다.

[문제 5] 클라우드 및 MSA 환경: 연계 데이터 보안 개념 및 아키텍처
시나리오
E 기업은 기존의 단일(Monolithic) 시스템을 클라우드 기반의 MSA(Microservice Architecture)로 전환 중입니다. 이에 따라 회원, 주문, 결제, 배송 등 여러 서비스 간에 API 호출을 통한 연계 데이터 통신이 실시간으로 빈번하게 발생하고 있습니다. 보안 담당자는 내부 서비스 통신이라도 절대 안전하다고 신뢰하지 않는 Zero Trust 관점의 연계 보안 아키텍처를 도입하고자 합니다.

질문

연계 데이터 보안의 기본 개념을 정의하시오.
 - 서로 다른 시스템 간 데이터를 송수신(연계)하는 과정에서 무단 접근, 탈취, 변조, 위변조 등을 방지하기 위해 전송 구간과 저장 구간(데이터 자체)의 암호화 및 보호 기술을 적용하는 모든 활동을 의미한다.


MSA 및 클라우드 환경에서 서비스 간 연계 데이터 보안을 강화하기 위해 적용할 수 있는 대표적인 전송 구간 보안 기술 및 인증 방식을 2가지 이상 제시하고 그 필요성을 서술하시오.
 - mTLS(mutual TLS : mutual Transport Layer Security - 상호 전송 계층 보안) : 기존 TLS(전송 계층 보안)가 클라이언트만 서버를 검증했다면(단방향성 인증), mTLS는 통신하는 두 서비스가 서로의 디지털 서명/인증서를 상호 검증(양방향성 검증)한다. MSA 환경 내 내부 네트워크 구간이라도 Zero Trust 보안 모델을 구현하여, 인가된 마이크로서비스 간의 통신만 허용하고 구간 내 데이터를 암호화한다.
 - OAuth2 및 JWT : 서비스 간 API 통신 시 사용자/서비스의 자격 증명을 매번 DB에서 확인하지 않고, 전달받은 JWT의 서명을 검증하여 빠르게 접근 권한을 확인한다. API 토큰 탈취 및 무단 API 위조 호출을 차단하기 위해 필수적으로 적용된다.
