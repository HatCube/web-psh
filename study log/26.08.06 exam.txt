문제 1

통합 구현을 적용해야 하는 이유 4가지는 다음과 같다
1. 기존 시스템과 신규 시스템간의 연계가 필요로한다.
2.업무의 자동화화 효율성을 높일수 있다.
3.이기종 시스템 데이터간의 일관성을 높일수 있다.
4.향후 시스템 시스템이나 기능을 확장할때의 확장성을 높일 수 있다.

이중 가장 중요한 것은 4번이며 자료에서는 기존 시스템은 계속 사용하나 향후 AI추천 서비스도 추가할 예정이기 때문에
확장성이 제일 중요하다고 판단했다.

문제 2

체크리스트 기법을 선택한 이유는 체크해야할 내용을 미리 정리하고 필요없는 내용을 제외하기 위함이다
체크리스트 기법을 활용하면 잔 실수가 줄고 요구사항의 누락의 가능성이 적어진다.
또한 체크리스트 기법을 활용하면 사람마다 다른 기준을 통일 시킬수 있다.

문제 3

연계 데이터 표준화를 수행해야 하는 이유는 일관성을 확보하고 데이터 간의 오류를 방지하며 유지보수 및 신뢰성을 확보하기 위함이다
또한 쇼핑몰 시스템과 ERP 시스템간의 수행해야할 표준화 작업은 코드 매핑으로 각 항목에 대한 이름을 통일해야하며,길이 또한 통일해야한다.

문제 4

프로젝트 책임자의 판단은 적절하지 못하다.
이유는 사용자 인터뷰를 통하여 자료와 함께 사용자 경험을 대조하여 정리가 필요한 부분 또는 유지해야 할 부분을 지정하지 않았으며
이로 인해 개발 시간 및 개발 비용이 증가하고 요구사항과 맞지 않을 수 있기 때문이다.

문제 5

반드시 작성해야 하는 문서는 인터페이스 정의서를 작성해야 한다.
인터페이스 정의서를 작성해야 하는 이유는 API의 방식,데이터의 형식,연계할 데이터 등을 확인할 수 있으며
추후 발생할 수 있는 오류나 장애상황에 대응하기 쉬워진다.
문서에 반드시 포함되어야 하는 내용은 API방식,데이터 형식, 연계 데이터,인터페이스 ID, 송신 데이터와 수신 데이터가 있다.

문제 6

연계 메커니즘의 개념은 데이터를 주고 받기 위해 필요한 데이터 방식이나, 전달방식, 처리 절차등을 정의화한 구조를 의미한다.
연계 메커니즘을 적용한 이유는 데이터 매핑 및 변환을 통해 ERP와 물류 시스템 간의 연계가 가능하기 때문이다.

문제 7

연계 데이터 생성 및 추출이란 송신 시스템 데이터 중 다른 시스템과 공유 하여야 하는 데이터를 지정하고 수신 시스템이 전달 받을 수 있는 데이터로 변환 하여 추출하는 것을 의미한다.
위 사례에서 연계 데이터 생성 및 추출이 중요한 이유는 필요한 데이터만 추출 하여 DB의 성능을 높이고 데이터 중복 및 전송 오류를 방지하기 위함이다.

문제 8

코드 매핑 및 데이터 변환의 개념은 데이터를 송신시스템과 수신 시스템끼리 데이터를 전송할 때의 데이터 통일 및 오류를 방지하기 위해 수행하는것을 의미한다
프로젝트 책임자가 코드 매핑 및 데이터 변환을 수행하기로 결정한 이유는 데이터 누락방지, 데이터 이름을 통일하지 않아 생기는 오류를 방지하기 위한것이며 또한 유지보수의 효율을 높이기 위함이다.

문제 9

인터페이스 테이블의 개념은 서로 다른 두 시스템의 연계를 위해 임시적으로 데이터를 생성하고 전달 받을수 있게 하는 테이블을 의미한다.

위 사례에서 인터페이스 테이블을 사용하는 이유는 하루의 수십만 건의 민원 데이터를 야간에 처리하기 위해 임시적으로 저장해야 할 공간이 필요하며, 데이터 전송중 오류가 발생하면 실패한 데이터만 처리할 수 있도록 인터페이스 테이블에서 데이터를 가져오기 위함이며
송신 시스템과 수신 시스템의 데이터 구조 통일을 하기 위함이다.

문제 10

로그는 시스템의 정보와 오류 또는 장애 발생시 명확하게 오류 또는 장애가 발생한 지점을 명확하게 확인하기 위하여 필요한 시스템이다.
로그를 기록해야 하는 이유는 데이터 전송 실패시 어느 부분의 오류로 인하여 전송이 실패하였는지 확인할수 있으며 어떤 데이터가 문제인지도 확인할 수 있기 때문이다.

문제 11

연계 모듈 구현 환경이란 송신 시스템과 수신 시스템 간의 데이터를 전달하기 위해 개발되는 환경을 뜻한다.
프로젝트 책임자가 구현 환경 변경 여부를 먼저 검토한 이유는 기존 연계 프로그램과 신규로 추가할 시스템의 호환성을 체크하고,오류 및 장애를 최소화 해야하기 때문이며,향후 시스템도 동일한 방식으로 연계해야하기 때문에 추후에 있을 연계도 수행해야 하기 때문이다.

문제 12

코드 매핑 테이블을 생성하는 이유는 송신 시스템과 수신 시스템이 서로 다른 데이터 코드를 사용해야 하기 때문에
송신 시스템의 코드와 수신 시스템의 코드를 미리 구별하고 파악하기 위함이다

오류 코드 테이블을 생성하는 이유는 연계 오류가 발생하면 오류 원인을 즉시 파악할 수 있어야 하고 운영중에도 코드가 바뀔 수 있기 때문에 오류 코드 테이블을 생성하여 오류의 위치 또는 원인을 바로 파악하기 위함이다.

로그 테이블을 생성하는 이유는 송신 시스템에서 수신 시스템 간 처리가 제대로 됬는지,오류 또는 장애가 발생하였다면 어디서 발생하였는지 파악하기 위함이다

문제 13

데이터 변환은 송신 시스템 데이터와 수신 시스템 데이터 사이의 이름을 통일하는 것이다.
송신 연계 응용 프로그램에서 데이터 변환을 수행해야 하는 이유는 송신 시스템과 수신 시스템의 코드 체계가 다르기 때문에 코드를 매핑할 때의 실수를 방지함과 동시에 추후에 발생할 수 있는 변환 중 오류에 대응하기 위해서이다.
코드 매핑을 함께 수행해야 하는 이유는 코드 매핑으로 코드를 미리 통일 시켜놔야 하기 때문이며 코드 매핑을 통해 개인정보 같은 민감 정보들을 미리 검열해야 하기 때문이다.

WSDL을 작성해야 하는 이유는 기능이나 호출 방법, 데이터 형식이나 규칙등을 미리 정의하여 각기 다른 개발자 끼리의 형식이 다른것을 예방하고 통일하기 위함이다

문제 15

연계 로그는 송신 시스템이 데이터를 추출하고 연계 데이터를 생성하여 수신 시스템에 전달할때의 과정을 기록한 문서이다.
연계 로그를 구현해야 하는 이유는 데이터를 추출하고 연계 데이터를 생성하여 수신 시스템이 수신받을 때 까지의 오류 또는 장애가 발생할 때의 오류 또는 장애의 위치를 파악하기 위함이며 운영 환경에서 로그를 지속적으로 관리해야 하는 이유는 로그에서 오류나 장애가 발생하기 전의 전조 현상을 체크하여 대응해야 실제 서비스 시의 오류와 장애를 줄일 수 있기 때문에 지속적으로 관리해야 한다.

문제 16

연계 데이터 보안이란 송신 시스템에서 수신 시스템까지의 전달 과정에서 데이터가 중간자 공격 또는 패킷 스니핑 등의 사유로 개인정보 또는 민감 정보가 유출되지 않고 데이터의 위변조를 막기위한 것이다.
담당자는 전송 구간에서 HTTPS만 적용하면 보안 요구사항이 모두 충족된다고 주장하였지만 이는 적절하지 않다.
이유는 HTTPS는 인터넷을 통해 외부에서 위변조를 방어하는 프로토콜이지만 전송 후 인터페이스 테이블에서는 보안 요구사항이 충족되지 못한다.
위 환경에서 전송 구간 보안과 데이터 보안을 모두 적용해야하는 이유는 전송 구간 보안은 송신 시스템에서 수신 시스템까지의 통신에서 전송 구간 보안이 필요하고 그 전송되는 데이터 내에서도 민감정보가 들어가 있을수 있기 때문에 민감정보를 미리 검열하거나 암호화해서 민감정보가 외부로 유출 되는것을 방지해야 하기 때문이다.
